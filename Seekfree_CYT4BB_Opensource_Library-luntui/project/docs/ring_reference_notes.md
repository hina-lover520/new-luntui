## 已复现的问题

在普通白路里放置一块规则矩形暗区，旧版合成图测试曾把这类图作为正确环岛：

```text
旧版：连续 4 帧后 phase=1，cap=100，detected=1；
      再经过 7 秒 phase=7，cap=0，fault=2。
修正：同样输入 phase=0，cap=-1，detected=0；
      再经过 7 秒仍为 phase=0，cap=-1，fault=0。
```

这证明旧识别和停车联动存在误触发路径，能造成减速后停车，但尚不能证明用户实车遇到的就是同一画面。原版输入相同并不能证明新增任务的耗时、误识别和接管时序不影响实车。

## 本次代码调整

1. 每帧逐行缓存白色通道，检测、补线与路径选择复用结果；删除对每个暗块候选重复向上逐像素搜索的做法。
2. 保留封闭内岛识别，同时增加参考代码式的左右侧入口：丢线、可靠对侧边界、上下拐点、内侧凸起及回转必须同时满足。普通单侧岔口没有内侧凸起时不接管。
3. 新环岛的封闭暗区必须有轮廓宽度变化；规则矩形暗块不再直接触发。这个保守门槛也可能漏掉某些实际内岛，需用车载画面核对。
4. 连续确认后先验证路径，近处白路与环道无法连通时继续普通循迹，不鸣叫、不限速、不进入环岛故障停车。
5. 控制端增加实际路径接管检查：原共享数组的状态必须已经为环岛状态，才能开始接受环岛限速。仅有候选命令、普通状态附带的错误限速或尚未接管的 FAULT 均不能让车停车。
6. 一旦真实接管，持续丢线和超时保护仍保留；不能通过取消所有保护掩盖错误路径。
7. 原版普通循迹公式、滤波、启动、舵机和平衡参数没有调整。识别和完成出环各短响一次的要求继续保留。
